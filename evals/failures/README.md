# 失败案例库

记录真实使用中发现的、**现有单测和 eval 都没覆盖到**的 bug，把它们变成永久的回归测试，
防止同类问题复发。对应路线图任务 19。

现在是空的——这不是没做完，而是故意不编造案例。里面应该放真实发生过的失败，不是假想的。

## 什么情况该往这里记

- 实际用 Neow 时遇到了一个 bug。
- **而且** `pytest` 跑过之后发现现有单测/eval 都没能catch住它（否则说明回归保护已经在
  别处存在了，不需要重复记录）。

如果 bug 很琐碎、单测能直接覆盖（比如一个纯函数的边界条件），直接在 `tests/` 里补单测
就够了，不需要经过这里——这里专门用于**端到端场景**：prompt 怎么写、模型怎么调工具、
结果哪里错了，这类只有跑完整 agent loop 才能复现的问题。

## 记录格式

复制 `TEMPLATE.md`，存成 `evals/failures/<yyyy-mm-dd>-<short-slug>.md`，填好四项：

- **Prompt**：触发问题的用户输入（或接近的复现版本）。
- **Expected**：当时期望的行为。
- **Actual**：实际发生的（错误输出、异常、文件状态错误等）。
- **Root cause**：定位到的根因，哪个文件/函数。

## 转成回归测试

记录完之后，在 `evals/tasks.py` 的 `TASKS` 里加一个 `EvalTask(..., category="regression")`，
用 `ScriptedClient` 复现同样的工具调用序列，`check` 断言修复后的正确行为。在任务的
`description` 里引用对应的 `evals/failures/*.md` 文件名，方便追溯。
